## 关键做法

- 模型 `claude-opus-5-5`、effort `high`、结构化输出（四项分数 enum 1–9 步长 0.5）、拒答服务端回退（`fallbacks: 'default'`）、`max_tokens` 16000、超时 180 秒、SDK 重试 2 次；不加提示词缓存（低频调用，写缓存反而多付）。
- 系统提示按任务固定，内嵌 `rubrics.json` 分档描述；作文放 `<essay>` 并声明其中指令不执行；Task 1 A 附图表数据与要点。
- 服务端再校验：四项缺一或重复即报错、条数截断、逐句修改标记是否在原文出现；总分按四项平均**向下取整到 0.5**（与自评一致）。
- 成本控制：每篇默认只批一次（`force` 重批）、每日上限 20（失败不计次）、同篇并发 409；结果与用量存在写作记录的 `ai` 字段。
- key 只在服务端环境变量，不回传前端；未配置时前端不显示入口。

## 验证

- `test:ielts-ai` 16 项（离线，假客户端 + `ANTHROPIC_BASE_URL` 指向不可用端口兜底）；变异检查：总分改四舍五入、失败也计次，各有用例失败。
- 前端：headless Chrome 检查页 28 项（标签、已有结果不请求、重批确认、force、进行中禁用、结果同步、失败保留旧结果、转义、关闭时两种显示）；记录页与计划页原有检查 48 + 10 项无回退。
- 端到端（临时档案 + 真实 `server.js`，假 key + 不可达的 API 地址）：status 为开启且不回传 key；真实 SDK 路径重试后返回 504 JSON，不计次、不写结果；400 / 404 正常。
- 合入后全部 IELTS 测试通过，`npm run validate` 0 错误 0 警告。
- **未验证**：真实 API 调用（本机没有凭据）——配置 `ANTHROPIC_API_KEY` 后运行 `npm run ai:smoke`；写作页交卷后的组件挂载未在浏览器实测。

## 已知限制

- AI 分有波动（约 ±0.5），只作参考；剑雅写作若也是自评，同样偏乐观。
- 不做口语 AI 批改；也还没有「写作错误本」（反复出现的错误进间隔复习）。
- 结果只存最近一次（重批会覆盖）；每篇的用量记在记录里，暂无汇总页。
