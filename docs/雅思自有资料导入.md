# 雅思自有资料导入

## 用途

把自己整理的雅思词汇、写作题、口语题导入系统，和内置内容一起出现在「🎓 雅思备考」的词汇 / 写作 / 口语页里，也能用 `/api/ielts/*` 接口查到。

- 导入的文件写到 `data/ielts/local/<type>/<分片名>.json`，schema 与内置分片相同。
- **自有资料仅本地使用，不会提交到仓库**：`data/ielts/local/` 已列入 `.gitignore`。工具每次运行都会打印这句提示。
- 只做「新增」：与内置内容或已有 local 分片重复的词 / id 一律报错，不会覆盖（原因见「冲突规则」）。

## 命令

```bash
node scripts/import-ielts-local.js <文件或目录> --type vocab|writing|speaking [--name 分片名] [--dry-run]
```

| 参数 | 说明 |
|---|---|
| `<文件或目录>` | `.json` 或 `.csv` 文件；也可以给一个目录，读取其中（不递归）全部 `.json` / `.csv`，合并成一个分片 |
| `--type` | 必填。`vocab` 词汇 / `writing` 写作 / `speaking` 口语。CSV 只支持 `vocab` |
| `--name` | 分片名，默认取文件名（去扩展名）或目录名。只能含字母（含中文）、数字、`-`、`_`，最长 64 字 |
| `--dry-run` | 只校验并打印摘要，不写文件 |

示例：

```bash
# 先试跑：只校验，不写文件
node scripts/import-ielts-local.js ~/ielts/我的词汇.csv --type vocab --dry-run

# 正式导入，写到 data/ielts/local/vocab/my-words.json
node scripts/import-ielts-local.js ~/ielts/我的词汇.csv --type vocab --name my-words

# 写作、口语用 JSON
node scripts/import-ielts-local.js ~/ielts/task2-extra.json --type writing
node scripts/import-ielts-local.js ~/ielts/speaking/ --type speaking --name my-speaking
```

输出示例：

```text
提示：自有资料仅本地使用，不会提交到仓库（data/ielts/local/ 已列入 .gitignore）
类型 vocab · 来源 我的词汇.csv · 目标 data/ielts/local/vocab/my-words.json
⚠️  我的词汇.csv 第 5 行 word=resilient: 缺少 phon

读取 3 条，跳过 1 条（空行），0 条有错误；错误 0 处，警告 1 条
✅ 已导入 3 条 → data/ielts/local/vocab/my-words.json
   条目: serendipity, ubiquitous, resilient
   重启服务（npm start）后生效：雅思内容加载器有内存缓存，运行中不会重新读取
```

- **错误（❌）**：阻止导入。只要有一处错误，整批都不写入，退出码为 1。
- **警告（⚠️）**：不阻止导入，比如缺音标、缺例句。最多列出 20 条，其余只计数。
- **跳过**：CSV 里的空行（所有列都为空的行）。
- 错误位置：CSV 写「文件名 第 N 行」（字段内换行时取该条记录的起始行），JSON 写「文件名 [下标]」（从 0 开始）。

## 导入后生效：需要重启服务

雅思内容加载器（`lib/ielts.js`）把内容缓存在内存里，没有运行时重新读取的接口。导入后要**重启服务**（停掉再 `npm start`）才能在页面和接口里看到新内容。

验证方法（以默认端口 3737 为例）：

```bash
curl 'http://localhost:3737/api/ielts/vocab?q=serendipity'
curl 'http://localhost:3737/api/ielts/writing/my-w2-01'
curl 'http://localhost:3737/api/ielts/speaking/my-s1-weather'
```

## 冲突规则

| 类型 | 判重依据 | 比较范围 |
|---|---|---|
| vocab | `word` 去首尾空格、转小写后相同 | 内置词汇 + 已有 local 词汇分片 + 本批 |
| writing / speaking | `id` 相同；写作和口语**共用一个 id 空间**（写作 id 不能和口语 id 重名） | 内置写作和口语 + 已有 local 分片 + 本批 |

**为什么没有 `--force` 覆盖**：加载器合并分片时，同一个 word / id 只保留第一次出现的那条，而内置分片总是先于 `local/` 加载，所以 local 里的同名条目永远不会生效。重复项还会让 `npm run validate` 报错。传入 `--force` 时工具会直接报错并说明原因。

**目标分片已存在时不覆盖**。要替换某个分片，先删掉旧文件再重新导入：

```bash
rm data/ielts/local/vocab/my-words.json
node scripts/import-ielts-local.js ~/ielts/我的词汇.csv --type vocab --name my-words
```

**建议**：自编的 id 加个前缀，比如 `my-`，避免和内置 id 重名（内置用 `w2-edu-01`、`w1a-01`、`w1g-01`、`s1-hometown`、`s2-person-01` 这类格式）。

**删除自有资料**：直接删 `data/ielts/local/<type>/` 下对应的文件，然后重启服务。

## Schema 与最小示例

所有文件都是 **JSON 数组**，每个元素是一个对象。完整字段说明见 [设计文档 §3](design/ielts-prep-mvp-20261124.md)；下面是导入时会检查的规则。

### vocab 词汇

```json
[
  {
    "word": "serendipity",
    "cn": "意外发现珍奇事物的本领",
    "topic": "culture",
    "cefr": "C1"
  }
]
```

| 字段 | 要求 |
|---|---|
| `word` | 必填，非空字符串 |
| `cn` | 必填，中文释义 |
| `topic` | 必填，见下方 topic 枚举 |
| `cefr` | 必填，`B1` / `B2` / `C1` / `C2`（大写） |
| `pos` | 可选，词性，如 `adj.`；缺失给警告 |
| `phon` | 可选，音标，如 `/ˌserənˈdɪpəti/`；缺失给警告 |
| `eg` / `egCn` | 可选，例句和译文；缺失给警告 |
| `academic` | 可选，`true` / `false`（CSV 不支持此列，需要的话用 JSON） |
| `collocations` | 可选，非空字符串数组，如 `["pure serendipity"]` |

topic 枚举：

| 值 | 含义 | 值 | 含义 | 值 | 含义 |
|---|---|---|---|---|---|
| `academic` | 学术通用 | `work` | 工作 | `globalization` | 全球化 |
| `education` | 教育 | `crime` | 犯罪 | `government` | 政府 |
| `environment` | 环境 | `media` | 媒体 | `culture` | 文化 |
| `technology` | 科技 | `urban` | 城市 | `science` | 科学 |
| `health` | 健康 | | | | |

### writing 写作

最小示例（Task 2）：

```json
[
  {
    "id": "my-w2-01",
    "task": 2,
    "topic": "education",
    "qtype": "opinion",
    "prompt": "Some people think homework should be banned in primary schools. To what extent do you agree or disagree?",
    "modelAnswer": "（范文，Task 2 至少 250 词，段落之间用 \n\n 分隔）",
    "modelBand": 7
  }
]
```

| 字段 | 要求 |
|---|---|
| `id` | 必填，只能含字母、数字、`-`、`_`，最长 64 字；与所有写作和口语 id 都不重复 |
| `task` | 必填，`1` 或 `2` |
| `prompt` | 必填，题目 |
| `modelAnswer` | 必填，范文。Task 2 至少 250 词，Task 1 至少 150 词（按空白切分计数） |
| `modelBand` | 必填，0–9、步长 0.5 的数字，如 `6.5`、`7` |

按题型的附加字段：

- **Task 2**：`topic`（同词汇 topic 枚举）、`qtype`（`opinion` / `discussion` / `problem-solution` / `adv-disadv` / `two-part`）必填；`promptCn`、`ideas`、`outline`、`phrases` 可选（后三个是字符串数组），缺失给警告。
- **Task 1 A 类（图表）**：`"variant": "A"`，必须有 `chart`：
  ```json
  { "type": "bar", "title": "…", "unit": "%",
    "categories": ["2010", "2020"],
    "series": [ { "name": "UK", "values": [12, 19] } ] }
  ```
  `type` 为 `bar` / `line` / `pie` / `table`，或 `process`（流程图）/ `map`（地图，结构见 `docs/design/` 与内置 `task1-academic-c.json`）；每个 series 的 `values` 必须全是数字，长度等于 `categories`；`pie` 只能有 1 个 series。`topic`（任意字符串）缺失给警告，`keyFeatures` 可选（字符串数组）。
- **Task 1 G 类（书信）**：`"variant": "G"`，`tone` 为 `formal` / `semi-formal` / `informal`，`bullets` 为非空字符串数组（信中要写的要点）。

### speaking 口语

最小示例（Part 1）：

```json
[
  {
    "id": "my-s1-weather",
    "part": 1,
    "topic": "Weather",
    "questions": [
      { "q": "What kind of weather do you like?", "sample": "I prefer cool, dry days, because I can walk outside comfortably." }
    ]
  }
]
```

| 字段 | 要求 |
|---|---|
| `id` | 同写作：格式限制，且与所有写作和口语 id 都不重复 |
| `part` | 必填，`1` 或 `2`（Part 3 追问放在 Part 2 条目的 `part3` 里） |

- **Part 1**：`topic` 必填（英文话题名），`topicCn` 可选（缺失给警告），`questions` 为非空数组，每项都要有 `q` 和 `sample`。
- **Part 2**：`category` 为 `person` / `place` / `object` / `event` / `experience` / `media`；`cueCard` 必须有 `title`、非空 `points` 数组和 `final`；`sample` 必填；`part3` 为非空数组，每项都要有 `q` 和 `sample`。
  ```json
  { "id": "my-s2-place-01", "part": 2, "category": "place",
    "cueCard": { "title": "Describe a quiet place you like to visit.",
                 "points": ["where it is", "how often you go there", "what you do there"],
                 "final": "and explain why you like this place." },
    "sample": "…",
    "part3": [ { "q": "Why do people need quiet places?", "sample": "…" } ] }
  ```

## CSV 模板（仅词汇）

```csv
word,pos,cn,eg,egCn,topic,cefr,phon,collocations
serendipity,n.,意外发现珍奇事物的本领,"Finding that book, by pure serendipity, changed her career.",纯属机缘巧合，找到那本书改变了她的职业生涯。,culture,C1,/ˌserənˈdɪpəti/,happy serendipity|pure serendipity
ubiquitous,adj.,无处不在的,"Smartphones are ubiquitous; even ""remote"" villages have them.",智能手机无处不在，连“偏远”村庄也有。,technology,C1,/juːˈbɪkwɪtəs/,ubiquitous presence|almost ubiquitous
```

规则：

- 第一行是表头。列顺序可以调整，列名不区分大小写；`word`、`cn`、`topic`、`cefr` 四列必须有，其余列可以不写；不认识的列名会报错。
- `collocations` 一格写多个搭配，用 `|` 分隔。
- **字段里有英文逗号、换行或双引号时，用双引号把整个字段包起来**；字段内的双引号写成两个 `""`。中文逗号（，）不需要处理。
- 每个值会去掉首尾空格；空着的可选列不会写进文件。
- 用 Excel 保存时选「CSV UTF-8（逗号分隔）」。文件开头的 BOM 和 Windows 换行（CRLF）都能识别。
- 词汇 JSON 和 CSV 可以放在同一个目录里一起导入。

## 常见错误怎么改

| 报错（节选） | 原因 | 改法 |
|---|---|---|
| `字段数 10 与表头 9 列不一致` | 某个字段里有英文逗号，但没加引号，被拆成了两列 | 用双引号把整个字段包起来：`"However, it works."` |
| `双引号没有闭合` | 引号字段少了结尾的 `"`，后面的内容都被当成了同一个字段 | 补上结尾引号；字段内的双引号写成 `""` |
| `引号字段结束后出现多余字符` | 写成了 `"abc"def` 这种形式 | 把整个字段放进引号：`"abc def"`，或去掉引号 |
| `表头: 未知列 … / 缺少必需列 …` | 表头拼错，或少了 `word` / `cn` / `topic` / `cefr` | 按 CSV 模板改表头 |
| `topic 非法 (feelings)` | topic 不在枚举里 | 改成上方 topic 枚举中的一个（小写英文） |
| `cefr 必须是 B1 / B2 / C1 / C2 (b2)` | 写成小写，或填了 A2 等不支持的级别 | 改成大写 `B1` / `B2` / `C1` / `C2` |
| `缺少 word` / `缺少 cn` / `缺少 prompt` … | 必填字段为空 | 补上该字段 |
| `与内置内容 vocab/academic.json 冲突（word 相同）` | 内置词表已经有这个词 | 从你的文件里删掉这条（内置已收录） |
| `与已有 local 分片 local/vocab/xxx.json 冲突` | 以前已经导入过 | 删掉这条；或删除旧分片，把新旧内容合并后重新导入 |
| `与内置内容 speaking/part1.json 冲突（id 相同）` | id 与内置条目重名（写作和口语共用 id 空间） | 换一个 id，建议加 `my-` 前缀 |
| `词重复 / id 重复（首次出现于本批 …）` | 同一批里写了两次 | 删掉或合并其中一条 |
| `id 只能含字母、数字、- 和 _` | id 里有空格、中文或其他符号 | 改成如 `my-w2-01` 的形式 |
| `范文仅 N 词，Task 2 至少 250 词` | 范文太短 | 补足字数（Task 1 至少 150 词） |
| `modelBand 必须是 0–9、步长 0.5 的数字` | 写成了 `7.3` 或字符串 `"7"` | 改成数字，如 `7` 或 `6.5` |
| `values 长度 … 与 categories 长度 … 不一致` / `pie 图只能有 1 个 series` | 图表数据对不齐 | 让每个 series 的值个数等于类别个数；饼图只保留一个 series |
| `目标分片 … 已存在` | 同名分片导入过 | 先删除旧文件，或用 `--name` 换个分片名 |
| `CSV 只支持 --type vocab` | 用 CSV 导写作或口语 | 写作、口语请用 JSON 数组 |
| `必须是 JSON 数组` / `JSON 解析失败` | 文件最外层不是 `[...]`，或有多余逗号等语法错误 | 外层用 `[ ]` 包起来；用编辑器的 JSON 检查功能定位语法错误 |
| `不支持 --force` | 加载器不允许 local 覆盖内置内容 | 去掉 `--force`，改掉冲突的 word / id |
| `导入后校验出现新错误，已回滚` | 写入后的全量校验发现了预检没覆盖的问题，文件已删除 | 按上方 ❌ 提示修改后重新导入 |

## 补充

- 工具会把校验结果和全量校验（`npm run validate`）保持一致：导入成功后，`npm run validate` 不会因为这批内容报错。
- 雅思内容目录可以用环境变量 `IELTS_DATA_DIR` 覆盖（测试夹具用），导入工具会写到 `$IELTS_DATA_DIR/local/<type>/`。
